# Технический анализ проекта "Планер Мод" (planner-app_mod)

## 1. Введение
Данный проект представляет собой минималистичное веб-приложение для планирования задач с интеграцией AI и использованием облачной базы данных Supabase. Основной упор сделан на эстетику "True Black" и продуктивность пользователя.

## 2. Анализ файловой структуры

Ниже представлен разбор каждого файла в корне репозитория:

*   **`README.md`**: Основная документация. Описывает возможности (AI-подсказки, PWA, облачная синхронизация), процесс установки и запуска, а также горячие клавиши.
*   **`AGENTS.md`**: Специальный файл с инструкциями для AI-агентов. Содержит ключевые команды, описание структуры проекта и правила работы с базой данных (RLS).
*   **`package.json`**: Определяет зависимости проекта. Мы видим React 18, Vite, TypeScript, а также библиотеки для Drag-and-Drop (`@dnd-kit`), уведомлений (`react-hot-toast`) и визуальных эффектов (`canvas-confetti`).
*   **`index.html`**: Главная HTML-страница. Подключает шрифты (Cormorant Garamond, DM Sans) и основной скрипт. Ссылается на отсутствующий файл `favicon.svg`.
*   **`vite.config.js`**: Конфигурация сборщика Vite с плагином для React.
*   **`tsconfig.json`** и **`tsconfig.node.json`**: Настройки TypeScript, определяющие правила компиляции и строгость проверки типов.
*   **`supabase_setup.sql`**: SQL-скрипт для настройки базы данных. Описывает таблицу `tasks` и политики безопасности (RLS), гарантирующие, что пользователи видят только свои задачи.
*   **`.env`**: Файл с переменными окружения (URL и ключи Supabase). **Внимание: содержит конфиденциальные данные!**
*   **`.eslintrc.cjs`** и **`eslint.config.js`**: Конфигурационные файлы ESLint. Присутствует конфликт форматов (старый `.cjs` и новый Flat Config).
*   **`.prettierrc`**: Правила форматирования кода (одинарные кавычки, отсутствие точек с запятой).

## 3. Технологический стек
*   **Frontend**: React 18, Vite, TypeScript.
*   **Backend**: Supabase (Database, Auth, Row Level Security).
*   **AI**: Anthropic API (предположительно для генерации задач).
*   **UX/UI**: Drag-and-drop сортировка, PWA (оффлайн режим), адаптивный интерфейс.

## 4. Особенности проекта
1.  **True Black UI**: Оптимизация под OLED-экраны для экономии энергии и снижения нагрузки на зрение.
2.  **Безопасность данных**: Использование RLS на уровне базы данных предотвращает несанкционированный доступ к чужим задачам.
3.  **Гибридный режим**: Поддержка гостевого входа через `localStorage` и полноценной синхронизации через Supabase.
4.  **Геймификация**: Система стриксов (🔥) и визуальные празднования (конфетти) при выполнении задач.

## 5. Выявленные недостатки и критические ошибки

### ❌ Отсутствие исходного кода (Критично)
В текущем состоянии репозитория **полностью отсутствует директория `src/`**. Это означает, что в проекте нет ни одного файла с логикой React-компонентов, стилей или утилит. Приложение невозможно запустить или собрать.

### ⚠️ Утечка конфиденциальных данных
Файл `.env` с реальными ключами доступа к Supabase был зафиксирован в истории Git. Это серьезная угроза безопасности. Ключи необходимо отозвать и перевыпустить.

### ⚙️ Конфликты конфигурации
Наличие одновременно `.eslintrc.cjs` и `eslint.config.js` может приводить к непредсказуемому поведению линтера. Рекомендуется перейти на единый формат (желательно новый `eslint.config.js`).

### 🖼 Отсутствующие ассеты
Файл `index.html` запрашивает `/favicon.svg`, но этого файла нет в корне или папке `public` (которая также отсутствует).

### 🧪 Тесты без кода
В `package.json` прописан запуск `vitest`, но сами файлы тестов отсутствуют (так как они должны находиться в папке `src/`).

## 6. Рекомендации
1.  **Восстановить папку `src/`**: Без нее проект является лишь набором конфигурационных файлов.
2.  **Обеспечить безопасность**:
    *   Немедленно сменить `ANON_KEY` в панели управления Supabase.
    *   Добавить `.env` в `.gitignore` (если это еще не сделано эффективно) и удалить его из истории Git с помощью `git filter-repo` или аналогичных инструментов.
3.  **Привести в порядок линтинг**: Удалить `.eslintrc.cjs` и настроить все правила в `eslint.config.js`.
4.  **Добавить иконку**: Создать или загрузить `favicon.svg`.
5.  **Настроить CI/CD**: Добавить проверку типов и линтинг перед деплоем, чтобы избежать подобных ситуаций с "пустым" репозиторием.

---
**Вывод:** Проект имеет отличную задумку и современный стек, но на данный момент он **неработоспособен** из-за отсутствия папки с исходным кодом и требует серьезного вмешательства в плане безопасности.
