# Технический анализ проекта "Планер Mod" ✦

Данный отчет представляет собой подробный разбор репозитория `planner-app_mod`. Анализ охватывает структуру файлов, используемый стек технологий, ключевые особенности версии "Mod", а также критические недостатки и проблемы безопасности.

---

## 1. Анализ файловой структуры и назначение файлов

В корне проекта находятся следующие конфигурационные и вспомогательные файлы:

-   **`package.json` & `package-lock.json`**: Определяют зависимости проекта и сценарии запуска. Здесь мы видим использование React 18, Vite, TypeScript и библиотек для Drag-and-Drop (`@dnd-kit`).
-   **`vite.config.js`**: Конфигурация сборщика Vite. Использует плагин `@vitejs/plugin-react` для поддержки React.
-   **`tsconfig.json` & `tsconfig.node.json`**: Настройки TypeScript, определяющие правила компиляции и строгость проверки типов.
-   **`supabase_setup.sql`**: SQL-скрипт для настройки базы данных в Supabase. Создает таблицу `tasks` с поддержкой Row Level Security (RLS), что критически важно для безопасности данных пользователей.
-   **`index.html`**: Главная точка входа в приложение. Подключает шрифты (Cormorant Garamond, DM Sans) и скрипт `src/main.tsx`.
-   **`.eslintrc.cjs` & `eslint.config.js`**: Конфигурация ESLint для обеспечения качества кода. Присутствие обоих форматов указывает на переходный период между старой и новой версиями конфига.
-   **`.prettierrc`**: Настройки форматирования кода для поддержания единого стиля в команде.
-   **`README.md`**: Описание проекта, его особенностей и инструкции по быстрому старту.
-   **`AGENTS.md`**: Специальный файл с инструкциями для ИИ-агентов, работающих с этим репозиторием.

---

## 2. Технологический стек

Проект построен на современном и производительном стеке:

-   **Frontend**: React 18 (с использованием хуков и функциональных компонентов).
-   **Сборка**: Vite (обеспечивает мгновенный запуск в режиме разработки и быструю сборку).
-   **Язык**: TypeScript (добавляет статическую типизацию, что уменьшает количество ошибок).
-   **Backend**: Supabase (PostgreSQL + Auth + RLS). Используется для хранения задач и аутентификации.
-   **Интерфейс**:
    -   `@dnd-kit`: Современная библиотека для реализации перетаскивания (Drag-and-Drop).
    -   `canvas-confetti`: Для визуальных эффектов (празднование завершения задач).
    -   `react-hot-toast`: Для всплывающих уведомлений.
-   **AI**: Интеграция с Anthropic API для генерации интеллектуальных подсказок.

## 3. Особенности версии "Mod"

Версия "Mod" отличается от стандартного планера рядом продвинутых возможностей:

1.  **Интеллектуальные функции**: Наличие `VITE_ANTHROPIC_API_KEY` в окружении и упоминание AI в документации говорят об автоматической генерации идей для задач.
2.  **True Black UI**: Интерфейс оптимизирован для OLED-дисплеев (чистый черный цвет), что экономит заряд батареи и снижает нагрузку на зрение.
3.  **Улучшенный UX**: Использование `@dnd-kit` позволяет пользователям легко менять порядок задач перетаскиванием.
4.  **Синхронизация**: Использование "atomic upserts" в Supabase гарантирует надежное сохранение данных даже при нестабильном интернете.
5.  **PWA**: Поддержка Progressive Web App позволяет устанавливать приложение на телефон или компьютер и работать в офлайн-режиме.

## 4. Критические недостатки и ошибки

В текущем состоянии репозитория обнаружены серьезные проблемы:

### ❌ Отсутствие исходного кода (`src/`)
Это самая критическая ошибка. В репозитории **полностью отсутствует папка `src/`**, которая должна содержать `main.tsx`, компоненты React, стили и бизнес-логику. Без этой папки проект не может быть запущен, собран или протестирован. Файл `index.html` ссылается на несуществующий путь `/src/main.tsx`.

### ⚠️ Проблема безопасности (утечка секретов)
Файл **`.env`** был зафиксирован в истории Git и находится в корне репозитория. Он содержит чувствительные данные:
-   `VITE_SUPABASE_URL`
-   `VITE_SUPABASE_ANON_KEY`
-   `VITE_ANTHROPIC_API_KEY`
Это позволяет любому, кто имеет доступ к репозиторию, использовать ваши облачные ресурсы и API ключи.

### 🛠 Проблемы конфигурации
-   **Дублирование конфигов ESLint**: Наличие и `.eslintrc.cjs`, и `eslint.config.js` может вызвать конфликты в инструментах разработки.
-   **Отсутствие `.gitignore`**: До последнего момента в репозитории отсутствовал файл `.gitignore`, что привело к попаданию служебных файлов и секретов в систему контроля версий.

---

## 5. Рекомендации

1.  **Восстановить исходный код**: Необходимо найти и добавить папку `src/` в репозиторий.
2.  **Обеспечить безопасность**:
    -   Немедленно отозвать (regenerate) ключи Supabase и Anthropic.
    -   Добавить `.env` в `.gitignore`.
    -   Очистить историю Git от конфиденциальных данных.
3.  **Причесать конфигурацию**: Оставить один формат конфигурации ESLint (желательно новый `eslint.config.js`) и удалить устаревший `.eslintrc.cjs`.
4.  **Настроить CI/CD**: Добавить GitHub Actions для автоматической проверки линтером и тестами при каждом пуше.
